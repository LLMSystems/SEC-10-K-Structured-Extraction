# Tier 2 外部參照驗證計畫：用獨立來源證明「邊界與內容定位對不對」

> 規則來源：[plan.md](../plan.md)（Tier 2 規則 7）　章節：[structure.md](../structure.md)（§4–5）　與 [deterministic validation plan](../deterministic_validation/validation_plan.md) 平行
> 資料：現有 `eval_datasets/ground_truth/`（34 份）**缺頁碼與邊界行標註**，Tier 2 需在同一批 filing 上**重新標註一層**（見「六、如何驗證驗證器本身」）

Tier 1 做到極限後仍驗不了一件事：**parser 的「定位本身」對不對**——因為要驗的正是 parser 自己的產物，拿產物驗自己是循環論證。
要打破循環，必須引入**與 regex 失敗模式無關的獨立來源**。本計畫處理這層。

---

## 一、為什麼必然需要 Tier 2（一句話回顧）

| Tier 1 能證 | Tier 1 證不了 |
|---|---|
| 區間幾何自洽、排序單調、內容量達地板（純看 parser 自己的 JSON） | 「Item 7 的起點究竟對不對」「尾巴有沒有被截掉」——這需要一個**不靠 parser 標題定位**的第二意見 |

人工驗證時的三個直覺，正好對應三個獨立來源：

| 人工直覺（[review.md](../review.md)） | 外部參照來源 |
|---|---|
| 「對應的頁碼有沒有跳來跳去」 | **頁碼**（來源 A） |
| 「item 該有的都在嗎、順序對嗎」 | **TOC**（來源 B） |
| 「這個 item 的頭尾有沒有被覆蓋到」 | **VLM 首尾行**（來源 C，主力） |

---

## 二、三個外部參照來源（總覽）

| 來源 | 第一性原理 | 為何與 parser 失敗模式獨立 | 驗什麼 | 成本 |
|---|---|---|---|---|
| **A 頁碼** | 紙本/PDF 是線性的，item 物理位置隨編號單調遞增，頁碼不該倒退或跳躍 | 頁碼來自**渲染後的版面座標系**，與 regex 在純文字流上的字元座標是兩套系統 | 邊界錯位、抓到文件他處的同名標題 | 低（一次渲染） |
| **B TOC** | 合法 10-K 的 TOC 自我宣告「應有哪些 item、什麼順序」 | TOC 是文件**自己宣告的結構**，與 parser 在內文逐段定位是獨立兩件事 | 漏抓 / 多抓 item、順序錯位 | 低～中 |
| **C VLM 首尾行** | 兩個失敗模式無關的方法若對「item 從哪行起、到哪行止」一致 → 信心趨近 100% | VLM vision 看的是**版面視覺**（粗體、字級、留白），regex 看字串 pattern，失敗模式不相關 | 邊界截斷 / 越界（頭尾沒對齊） | 中（依模型與頁數） |

> 三者共同價值是**三角驗證**：兩個獨立方法一致 → 信心趨近 100%；不一致 → 自動標記人工複查。

---

## 三、共用設施

- **渲染管線**：`HTML → PDF → 頁面圖`（headless 渲染）。同時建立 **`char_offset → 頁碼` 對照**（渲染時記錄每頁涵蓋的字元區間），讓 parser 的 `char_range` 能映射到頁碼。三來源都依賴它。
- **GT 擴充標註層**（Tier 2 專用，見第六節）：在現有 34 份上補標 ① 每個 item 起始頁碼 ② TOC 宣告的 item↔頁碼 ③ 每個 item 的**視覺第一行 / 最後一行**（必須是渲染版面上看到的行，非純文字流首末）。
- **VLM 呼叫封裝 + pass@k / pass^k harness**：同一輸入可重複問 k 次，統計穩定度（第六節）。
- **比對度量**：首尾行用 `rapidfuzz`（已在 `requirements.txt`）做 fuzzy match，設相似度門檻；頁碼 / TOC 用集合與序列比對。

## 四、來源 A — 頁碼一致性

**第一性原理**：渲染後文件是線性的，extracted item 的起始頁碼**隨編號單調遞增**；單一 item 的內容不該散落在不連續的頁。

**目標錯誤**：item 定位跳到文件他處（例如抓到 TOC 裡的「Item 7」字樣而非正文），導致頁碼倒退或亂跳。

**做法**
1. 渲染 → 取得 `char_offset → 頁碼` 對照。
2. 把每個 extracted item 的 `start_char` 映射成 `start_page`。
3. 檢查：依編號排序後 `start_page` 單調不遞減；單一 item 的 `[start_char, end_char]` 不跨越不連續頁。

**驗什麼**：邊界錯位、抓到他處同名標題。
**侷限**：HTML filing 沒有原生「頁」，渲染出的頁是人造的；單調性檢查**依賴渲染確定性**（同一輸入每次渲染分頁一致）。原始 10-K 常印有頁尾頁碼（preprocess 已注入 `[[PAGE]]` 標記），可作為交叉佐證，但格式不穩，以渲染頁碼為主。

## 五、來源 B — TOC 交叉驗證

**第一性原理**：TOC 是文件自己宣告的「應有結構」，獨立於 parser 在內文的定位。

**目標錯誤**：**漏抓一個 item**（這正是 Tier 1 規則 3「大段空隙」很可能被降級成啟發式的那條 → 這裡用 TOC 補強）、順序顛倒。

**做法**
1. 解析 TOC 區塊（regex 抓 TOC 段，或交給 VLM 回報 TOC 列出的 item）→ 得到**宣告的 item 清單 + 宣告頁碼**。
2. 集合比對：parser 抓到的 item 集合 vs TOC 宣告集合 → 找漏抓 / 多抓。
3. 序列比對：parser item 的頁碼順序 vs TOC 宣告頁碼順序。

**驗什麼**：漏抓 / 多抓 item、順序錯位。
**侷限**：TOC 本身可能格式雜或有誤；Part III 的 `incorporated_by_reference` item 在 TOC 仍會列出 → 比對時需對齊 status 預期，不能把「TOC 有、parser 標 by_reference」當成漏抓。**獨立性前提**：若 TOC 也用「來源 C 的同一個 VLM」解析，兩者共享失敗模式 → 三角驗證的證明力下降（見誠實邊界 4）。

## 六、來源 C — VLM 首尾行比對（主力，plan.md 規則 7）

**第一性原理**：兩個失敗模式無關的獨立抽取方法，若對「item 第一行 / 最後一行」一致 → 信心趨近 100%。

**目標錯誤**：邊界截斷（尾巴少抓）或越界（頭跨進前一個 item）。

**做法**
1. 把 item 起始 / 結束所在頁面渲染成圖。
2. 請 VLM 回報該 item 的**第一行**與**最後一行**（純文字）。
3. 與 parser `content_text` 的首行 / 末行做 fuzzy match。
4. 一致 → PASS；不一致 → 標記人工複查。
5. **不需餵整份文件**，只需邊界附近頁面 → 成本可控。

**驗什麼**：邊界截斷 / 越界（頭尾沒對齊）。
**獨立性**：VLM 看版面視覺、regex 看字串 pattern，失敗模式不相關 → 一致即強證據。

## 七、如何驗證「驗證器本身」

Tier 2 與 Tier 1 最大不同：**驗證器內含一個本身會出錯、會隨機漂移的元件（VLM）**。所以不能假裝它是真值，要先量化它的可靠度，再決定用不用、用哪個模型。

### 7.1 GT 需要重新標註（前提）

現有 34 份 GT 只有 `(item_number, char_range, content_text, status)`，**沒有 Tier 2 需要的**：

| 來源 | 缺的標註 |
|---|---|
| A 頁碼 | 每個 item 起始頁碼 |
| B TOC | TOC 宣告的 item↔頁碼 對照 |
| C VLM | 每個 item 的**視覺第一行 / 最後一行**（渲染版面上的行，非純文字流首末） |

→ 需建立 **Tier 2 標註層**：在同一批 filing 的渲染 PDF 上補標。可擴充 [SEC-10-K-Annotation-Tool](https://github.com/LLMSystems/SEC-10-K-Annotation-Tool)，或在渲染頁上人工標。份數可先抽樣子集驗證流程，再決定是否全標（見待確認）。

### 7.2 選哪個 VLM：pass@k / pass^k

VLM 有不確定性——同一頁問 k 次首尾行可能答不同。**生產用的驗證器若同一份 filing 跑兩次給出相反結論，它自己就不可信**。所以先量穩定度再選模型：

| 指標 | 定義 | 衡量什麼 |
|---|---|---|
| **pass@k** | 問 k 次，**至少一次**與 GT 邊界行一致即算過 | 模型**有沒有能力**答對（能力上界） |
| **pass^k** | 問 k 次，**k 次全部**與 GT 一致才算過 | 模型**穩不穩定 / 能不能信**（可靠度，生產驗證器要求此項高） |

- 在重新標註的 GT 上，對候選模型各跑 pass@k 與 pass^k。
- **以 pass^k 為主要選型依據**：pass^k 不夠高代表結果會漂，不能當驗證器。
- 報告每個候選模型的 `{pass@1, pass@k, pass^k, 平均成本/頁, 延遲}`。

### 7.3 精確度 / 偵測率（沿用 tier_1 精神，對象不同）

| 測試 | 資料 | 通過條件 | 與 Tier 1 的差異 |
|---|---|---|---|
| **精確度 / 不誤殺** | 重新標註的**正確** GT | 低誤報 | Tier 1 的 FP=0 是邏輯保證；**Tier 2 做不到結構性 0**——VLM 不確定性 + fuzzy 門檻都會貢獻偽陽性，只能靠 pass^k + 門檻校準壓低 |
| **偵測率 / 抓得到** | 在 GT 上注入邊界錯誤（截斷首/尾行、整段位移、刪一個 item） | 對應錯誤必觸發 | operator：`truncate_tail` / `shift_head`（給 C 用）、`drop_item`（給 B 用） |

## 八、誠實邊界（必寫）

1. **渲染 ≠ 原始版面**：HTML 無原生頁，渲染出的頁是人造的；頁碼單調性檢查依賴渲染確定性，換工具或 CSS 可能改變分頁。
2. **VLM 不確定性**：驗證器引入了一個會出錯、會漂移的元件——用 pass^k 量化它，而非假裝它是真值。Tier 2 的「高信心」是**統計可靠度**，不是 Tier 1 那種邏輯必然。
3. **成本 vs 覆蓋**：只驗邊界頁面成本可控但不驗中間內容；全頁驗證成本高。本計畫預設只驗邊界。
4. **獨立性是假設、不是保證**：三角驗證的證明力建立在「兩來源失敗模式無關」。若 TOC 與首尾行共用同一 VLM，假設被打破，一致性的說服力下降——選型時要留意來源間的相關性。
