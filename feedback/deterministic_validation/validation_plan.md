# Tier 1 規則驗證計畫：用 Ground Truth 證明「違反 → 高信心錯」

> 規則來源：[plan.md](../plan.md)　資料：`eval_datasets/ground_truth/`（34 份人工標註 10-K）

每條規則都是一個可被經驗檢驗的主張：**「違反 → 高信心錯」**。
要證明它，必須同時通過兩個方向相反的測試，而且兩者證明的東西不同。

---

## 一、證明框架（所有規則共用）

| 測試 | 資料 | 通過條件 | 證明什麼 | 證明力 |
|---|---|---|---|---|
| **精確度 / 不誤殺** | 34 份**正確** GT 直接跑規則 | **零觸發**（FP rate = 0） | 正確的解析不會違反 → 這是主張的反面 | **能否證**：1 個正確 GT 觸發就推翻主張 |
| **偵測率 / 抓得到** | 在 GT 上**注入對應錯誤** | 對應錯誤**必觸發**（recall 高） | 規則真能抓到它宣稱的錯 | **只能支持**：34 份是歸納非證明 |

關鍵原則：**精確度測試是主力**（它能「否證」一條規則），偵測測試是輔助（確認規則接線正確、找出運作門檻）。

## 二、共用設施

- **Gold parse**：把每份 GT 視為「正確的解析輸出」= `(item_number, char_range, content_text, status)` 清單。**四條規則全部只需 JSON**。
- **空隙度量（規則 3）**：用**原始字元空隙** `start[i+1] − end[i]`（純 JSON 整數）。
- **內容總量（規則 4）**：用 `S = Σ len(content_text)`（status=extracted 的 item 加總，純 JSON）。規則 1 的 `end ≤ len(T)` 那半條雖需全文長度，但實務上不可能被違反，可忽略。
- **Mutation harness**：`mutate(gold, operator, params) → wrong_parse`，對 gold 注入「單一類別」的錯，其餘保持合法。每條規則配對專屬 operator。
- **產出指標**：每條規則 → `{FP rate（34 份）, 各 operator 的 recall, 門檻（若有）, 判定}`。

---

## 規則 1 — 區間合法 `0 ≤ start < end ≤ len(T)`

**目標錯誤**：幾何不可能的區間（反向 / 越界 / 零長度）。

**資料創造**
- 正確集：34 份 GT 的所有 extracted 區間。
- 注入 operator（每份隨機挑 1 個 extracted item 改）：
  - `reverse`：`(start, end) → (end, start)`
  - `oob`：`end = len(T)+k` 或 `start = -k`
  - `zero`：`end = start`

**驗證方法**
- 精確度：34 份 GT → 期望 0 觸發（確認 GT 本身幾何合法、檢查有接線）。
- 偵測率：所有 mutant → 期望 100%。

**通過標準**：FP = 0 且 recall = 100%。
**侷限（要寫明）**：此規則是純邏輯，注入 → 觸發近乎**套套邏輯**（在驗 if 判斷式）。GT 的價值在「確認 34 份正確資料零誤殺」這個回歸性保證，而非發現新事實。

---

## 規則 2 — 依編號排序後 start_char 單調、區間不重疊

**目標錯誤**：item 定位錯位 / 順序顛倒 / 相鄰區間重疊（對應「選錯候選」這類**寫實**錯誤）。

**資料創造**
- 正確集：34 份 GT（按編號排序後，gold 區間本應單調且不重疊）。
- 注入 operator：
  - `swap`：交換相鄰兩個 extracted item 的 `char_range`
  - `overlap`：`end_i = start_{i+1} + δ`（δ 取數百～數千字）
  - `displace`：把某 item 的區間整段搬到較前的隨機位置

**驗證方法**
- 精確度：34 份 GT → 期望 0 觸發。**這是真實有效的測試**：若有 GT 觸發，代表 GT 內部不一致或規則過嚴，須回查。
- 偵測率：各 operator 分別統計 recall。

**通過標準**：FP = 0；`swap`/`overlap` recall ≈ 100%，`displace` 隨位移量遞增。
**為什麼有說服力**：注入的錯誤是 parser 真實會犯的（定位錯位），精確度測試又跑在真實正確資料上 → **這是整組裡此方法最能服人的範例規則**。

---

## 規則 3 — 相鄰 extracted item 間不該有大段未指派文字

**這條最可能被 GT 反證**，而「用 GT 把它從不變量降級成啟發式」本身就是最有力的一段分析。

**目標錯誤**：中間漏抓一個 item（其文字無人認領）。

**資料創造**
- 正確集分析：對 34 份 GT，計算每一對相鄰 extracted item 之間「未被任何 extracted 區間覆蓋」的空隙大小（原始字元 `start[i+1] − end[i]`，純 JSON），並**標記每個空隙是否合法**（其間是否夾著 by_reference / not_applicable / reserved item，或屬封面 / 簽名頁 / 附錄）。→ 得到**正確解析下的「合法空隙」分佈**。
- 注入 operator：`drop_item` — 取一個 extracted item，把 status 改 missing、`char_range` 設 null，但**不把它的文字併給鄰居** → 製造一個真實的「漏抓空隙」。

**驗證方法（重點在精確度）**
1. **精確度**：用候選門檻在 34 份 GT 上跑。統計有多少**正確**解析被誤觸發——預期 Part III 大量 by_reference 會在相鄰 extracted（如 Item 10 ↔ Item 15）之間留下合法大空隙 → **很可能 FP > 0**。
2. **門檻校準**：把「合法空隙分佈」與「`drop_item` 空隙分佈」畫在一起，看是否存在一個門檻能乾淨分開。**若兩者重疊 → 證明不存在 FP=0 的門檻 → 此規則不能算高信心不變量。**
3. **精煉版對照**：再測「排除被中間非 extracted item 解釋的空隙」後的版本，用 GT 量化 FP 下降多少。

**通過標準（誠實版）**：若任何能達到可用 recall 的門檻都使 FP > 0 → **判定為「啟發式告警」層，移出「違反一定錯」**。
**為什麼有說服力**：這是用證據做降級決策，而不是憑感覺。GT 在這裡扮演「篩子」，自動把偽裝成不變量的門檻揪出來。

---

## 規則 4 — extracted item 內容字數總和不得低於絕對地板

度量：`S = Σ len(content_text)`（status=extracted 的 item 加總，純 JSON）。
**目標錯誤**：抓錯主文件 / preprocess 把內容清空 / 幾乎沒抽到任何內容。

**資料創造**
- 正確集：34 份 GT 的 `S` → 得到觀測最小值。
- **地板必須先驗設定**（取自「合法 10-K 必有的最低內容量」，遠低於任何真實值），GT 只用來**確認沒踩到**，不可用來定義地板（否則就退回統計校準，正是要避免的）。
- 注入 operator：
  - `gut`：把多數 extracted item 的 content 清空、status 改 missing → `S` 崩塌（模擬抓錯檔 / 內容被清光）
  - `keep_one`：只留一個短 item（模擬只解析到封面 / 單張附錄）

**驗證方法**
- 精確度：34 份 GT → 期望 0 觸發；報告**安全邊際** = `min(GT 的 S) / 地板`（應有數倍以上）。
- 偵測率：`gut` / `keep_one` mutant → 期望觸發。

**通過標準**：FP = 0 且安全邊際足夠大（例如 ≥ 10×）。
**侷限**：GT 只能證「這 34 份的 `S` 都遠高於地板」，**不能證「任何合法 10-K 都不會更低」**——高信心建立在先驗地板 + 大安全邊際，而非 GT 本身。

## 總產出（報告用一張表）

| 規則 | 精確度（34 份 FP） | 偵測率 | 此法證明力 | 判定 |
|---|---|---|---|---|
| 1 區間合法 | 預期 0 | ~100%（套套） | 低（靠定義） | 不變量，GT 作回歸保證 |
| 2 單調非重疊 | **實測，預期 0** | swap/overlap ~100% | **高（錯誤寫實）** | 不變量，**範例規則** |
| 3 大段空隙 | **可能 > 0** | drop_item 可測 | 高（能降級） | **很可能降為啟發式** |
| 4 內容總和地板 | 預期 0（看邊際） | gut/keep_one 可測 | 中（靠先驗地板） | 不變量*（前提：先驗門檻）* |

## 方法的三個誠實邊界（必寫）

1. **精確度能否證、偵測只能支持**：34 份能用一個反例推翻一條規則，但無法證明對所有未見 filing 普世成立。
2. **對純邏輯規則（1、4 的注入），偵測測試是套套邏輯**——真正有資訊量的是精確度測試與寫實錯誤（規則 2、3）。
3. **注入錯誤 ≠ 真實 parser 錯誤**：偵測率算的是「想得到的錯」的覆蓋率。更可信的 recall 應另外拿 **parser 真實出錯的歷史案例**來跑，作為 mutation 的補充。
